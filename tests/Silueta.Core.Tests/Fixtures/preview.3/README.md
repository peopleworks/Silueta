Synthetic files generated by a standalone .NET 10 console application referencing **NuGet
`Silueta.Core` 0.3.0-preview.3**, with no ProjectReference to the current Core project. Its package SHA-256:

`655b376d425928bc1f1158cab8846b5c31f3c7f7c4cef8e7ad824f34fb23e13f`

The input lineage exercises pools, labels, generalizations, values, lists, a custom pattern and a named
policy. The generator assigned `Ale Bravo`, reminted to the only remaining head (`Noa Bravo`), and
redacted the synthetic input with this lineage. Only the random code and run timestamp were normalized
to fixed synthetic values. The original package generated every manifest field and fingerprint.
The fixture's `[REMOVED]` phone output is the old package's fallback when its supplied labels omit Phone.

`PersistenceCompatibilityTests` checks readable associations, code/name/history round-trip, unchanged
lineage/policy fingerprints, historical manifest fields, and reproducible example output. Algorithm
fingerprints in a historical manifest are preserved as data, not imposed on every future detector.

The source is [`GenerateFixtures.cs.txt`](../../../../tools/compatibility/GenerateFixtures.cs.txt).
To reproduce, make a standalone console project outside the main test sources, add a PackageReference
to exactly `0.3.0-preview.3`, copy that source as `Program.cs`, and pass a fresh output directory.
Compare generated files with these fixtures. Do not regenerate the baseline with current Core merely
to make a regression pass. The generator normalizes the code to a public fixture value, so these files
contain no private or real-person data.
